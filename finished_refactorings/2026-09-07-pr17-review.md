# PR #17 Codex review loop

Route: Standard; bounded fixes per review round. The user explicitly authorizes
committing, pushing and requesting further Codex reviews until no actionable
findings remain, overriding the standing no-commit default.

## Contract and acceptance

- Judge each Codex finding against current code and behavior; fix valid findings
  and explain non-issues with evidence in the PR.
- Preserve existing async lifecycles, test seams and UI boundaries. Regression
  tests use the existing viewer harness and tracked file-work completion.
- Focused tests prove each fix before commit/push. Run `make verify` for the final
  candidate, retaining raw race-test streams if a failure needs diagnosis.
- Request another Codex review on the pushed commit and wait for its completed
  result. A running review, lack of inline comments or clean earlier commit does
  not establish approval of the current head. Do not merge the PR.
