01

Complete image records inside imaging

Strongin-processThree full-image callers
internal/imaging/loader.go:98-107internal/ui/load.go:140-147internal/ui/load.go:435-440internal/ui/compare.go:60-74
Problem
The imaging module is deep for pixel decoding, but its full-image interface leaves size and EXIF facts to three callers; comparison omits both (MA-006).
Direction
Concentrate full-image record completion in the existing imaging implementation, retaining early header access and the cheap thumbnail decode path.
Deletion test
Deleting the decoder would scatter format knowledge across callers; keep it, and remove caller-owned record assembly so completeness gains one home.
Seam / adapter
Deepen the existing full-image seam; no interchangeable adapter is needed for pure record completion, and storage remains behind its existing reader.
Test surface
Test pixel/size/EXIF agreement through the full-image interface, then retain thin caller tests for early resize and Add versus AddIfFits; source facts gain locality.
  • Depth: complete results, fewer obligations
  • Leverage: one fix, three callers
  • Locality: image facts stay together
Constraint preserved: loader.go deliberately skips EXIF work for thumbnails. Do not turn every decode into a full metadata read.
02

Keep duplicate validity with the model

Strongin-processSearch, browse, hash completion
internal/dupes/groups.go:48-119internal/dupes/dupes.go:171-207internal/ui/grid/dupes.go:301-320internal/ui/grid/search.go:107-120internal/ui/grid/hashengine.go:164-201
Problem
The duplicate module exposes a shallow validity interface: Grid must coordinate Compute/Install and distance checks, while fact writes can accept obsolete work (MA-008, MA-009).
Direction
Bring fact freshness and accepted group snapshots into the existing model implementation; keep worker scheduling and Grid result presentation outside it.
Deletion test
Deleting the model would push grouping and visibility back into Grid; instead delete caller-owned validity choreography and concentrate it in the model.
Seam / adapter
Keep the Fyne-free snapshot seam: the live file-set adapter and test snapshot adapter already vary; another scheduler interface is not justified yet.
Test surface
Through the model interface, reject old-generation facts/results and reuse unchanged groups; retain Grid tests for highlight, query and queued presentation.
  • Depth: validity behind one interface
  • Leverage: search reuses accepted groups
  • Locality: stale-work rules live together
Constraint preserved: greedy complete-linkage groups and highest-resolution representatives stay unchanged; model ownership does not mean moving Fyne or worker orchestration into it.

Let wallpaper own retained image files

internal/wallpaper/wallpaper.go:10-14internal/ui/wallpaper.go:60-98internal/ui/wallpaper.go:98-194internal/ui/wallpaper_test.go:264-340
Problem
The wallpaper module’s interface requires a persistent file, while both UI entries acquire exclusion and UI owns its platform-sensitive lifetime.
Direction
Explore deepening the wallpaper module so its implementation owns exclusion, copy creation, apply and retention; UI keeps eligibility, exact pixel capture and localized feedback.
Deletion test
Deleting applyWallpaper would duplicate real work in two callers, so keep that sequence; absorb its remaining ownership obligations instead of merely moving the file.
Seam / adapter
Keep the platform adapter and controlled test adapter at an internal seam; real temporary files suffice, so a general filesystem interface would add no depth.
Test surface
Test overlap, failed-copy rollback and Target display retention through the operation interface with tiny images; keep viewer tests for source capture and feedback.
  • Depth: lifetime hidden from callers
  • Leverage: both actions share exclusion
  • Locality: retention tests leave viewer
Placement decision to revisit: mosaic ticket 11 assigns viewer.wallpaperDir. The test burden supports exploring a new owner; its one-lifecycle and target-safety requirements remain constraints.
