Copy Selection Feature

Problem

Copy Selection mode occupancy leaks across sixteen files. keys.go keeps a second table of which keys cancel, which zoom, which stay. Item 9 in needs_refactoring.md is the same positional encoding, now with one more mode.

Solution

Concentrate yield policy in one module that command entry already has to cross. Do not invent a feature registry: Copy Selection is still the only occupant, so a generic occupancy seam would be hypothetical.

Wins

  • locality: busy policy in one place
  • keys.go stops duplicating HandleKey
  • leverage: next mode reuses yield
  • sixteen call sites become composition
Repo convention, not an ADR: cross-feature decisions stay in internal/ui; do not grow a shared controller. One occupant means a generic occupancy seam is still hypothetical.

After — small seam, depth in apply

interface

read preferences · apply change · two update verbs

implementation

tabs · validation ceilings · cache retune · appearance · manual-update dialogs

depth: form and side effects hide behind the seam

Problem

settingswin.Host is thirty-two methods, field-for-field with the form. Deleting the Host does not remove that surface — it reappears 1:1 on the viewer. fakeHost already proves two adapters, so the seam is real; it is just shallow.

Solution

Drive the window from the standing preferences value plus a small apply path for live side effects. Keep CheckForUpdatesNow / PerformUpdate as the only update verbs. Tests hit that seam instead of mirroring every getter.

Wins

  • interface shrinks to preferences + apply
  • leverage: new setting is one field
  • fakeHost stops tracking 30 methods
  • matches the menus/infoview snapshot pattern
Applies the documented exception in AGENTS.md: default to a narrow Host; reach for a value snapshot when the Host would be a dozen-plus methods. menus already took that turn. Settings writes have live side effects, so apply cannot be a pure snapshot.

load module

Problem

display extracted frames and rotation; the load choreography stayed on the viewer. Copy Selection’s freeze now reaches through load.go, so a new caller had to learn the animation loop’s internals.

Solution

Only if candidate 1 does not absorb the pause as an internal seam. Then concentrate ShowImage / finishLoad / animate / vector behind one load interface the viewer composes.

Wins

  • locality: load steps in one module
  • pause is a load seam, not a viewer field
  • deletion test: choreography would reappear
Reopens the 2026-08-28 viewer field-cluster plan, which stopped at display on purpose. A load Host risks becoming as wide as the pipeline. Prefer candidate 1 first; this only pays if pause still has a second caller afterwards.
